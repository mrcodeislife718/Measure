SECURITY

Measure Security

Measure is built around evidence integrity and distrust of unsupported claims. The production service uses secure cookie sessions, hashed API keys, organization-scoped authorization, usage entitlements, rate limits, Stripe webhook verification, row-level database controls, HTTPS security headers, tamper-evident evaluation evidence, and private-runner result verification.

Private execution

Private and Enterprise customers can run supported evaluations inside customer-controlled infrastructure. The local runner can interact with HTTP or command participants and produce a digest-protected result package for ingestion by Measure.

Secrets

Do not submit passwords, API secrets, payment credentials, or unrelated sensitive records through the public demo or contact form. Production secrets belong in protected environment-variable stores, not source control.

Responsible disclosure

If you believe you found a security vulnerability, use the private contact form, select Security, describe the affected surface and reproduction steps, and avoid accessing data that is not yours. Do not post vulnerability details in a public GitHub issue before remediation.

Evaluation evidence

A Measure result describes a tested scope, version, world, verifier set, and evidence lineage. It does not certify absolute security or guarantee future behavior outside those conditions.
